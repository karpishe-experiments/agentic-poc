# M6 — Bounded agent improvement and closeout

**State:** Planned. **Coverage:** AC07–AC08, AC10 and experiment conclusions.
**Predecessor:** [M5](M5-real.md). Apply [EXECUTION](EXECUTION.md).

## Entry gate

Read M5's retained runs, failures, reports and usage, then revise this file with
actual findings. Verify that assets and configuration evidence remain available.
Keep the accepted Real baselines immutable. Bundle remaining Dify/login/release
handoffs before implementation. No new paid campaign is implicitly authorized.

Scope is one evidence-led improvement pass, not perfection. Select the smallest
agent/prompt/delegation/workflow correction that addresses a repeated observed
failure or warning. If there is no material supported improvement, document that
result and close the milestone without inventing work or spending.

## Work sequence

1. Summarize each persona's completion, intent adherence, consistency, interaction
   burden, requests, duration and available cost. Separate tester opinion, judge
   opinion and deterministic facts. Do not compare simulated visual scores with
   Real quality as though they were equivalent evidence.
2. Rank concrete findings by impact on completion/creator intent, then cost/UX.
   Prefer agent instruction, context routing or workflow changes. Record code
   defects separately; fix only those necessary for the accepted experiment.
3. Back up the affected Dify configuration privately, retain sanitized hashes and
   change rationale, implement the bounded correction and update fixtures.
4. Run affected Simulated cases and static/contract checks. Obtain two consecutive
   clean independent reviews. Publish/sync/read back the Dify version. Use the
   app PR/CI/deploy procedure only when application code actually changed.
5. If a Real/Balanced comparison is needed, request a finite campaign at entry
   (models, per-run and total calls, successor allowance). Without it, report the
   improvement as simulated-verified and its real effect unverified. Never rewrite
   baseline evidence or run paid calls merely to complete a documentation table.
6. Compare any authorized successors against baseline on the same brief/layout.
   Keep quality warnings; no zero-warning or top-score exit threshold.

## Documentation and handoff

Reconcile PRD, roadmap, these milestone exit records, implemented architecture,
canonical Dify operating matrix and setup guide. Remove obsolete instructions
that seed/edit local runtime agents for the new profile. Explain the new normal
booklet IDs, suite publication/tool synchronization, pause/recovery and reference
lineage. Keep one current operating procedure, not duplicated incident logs.

Record verified lessons: external agent configuration, specialist delegation,
operator automation, simulation limits, image consistency/lettering, warning-based
completion, provider accounting and cost visibility. Distinguish failed hypotheses
and missing measurements from established facts. Link retained evidence.

Perform a requirement-by-requirement PRD AC01–AC13 audit using actual code, tests,
run records, Dify versions and staging behavior. Documentation assertions alone
do not prove acceptance. Any technical gap returns to the owning milestone;
quality warnings remain advisory. Update issue #65 evidence with achieved outcomes
and limitations. Issue closure requires its separate authorization.

## Exit

Two clean reviews of the final changes, required CI and any needed staging checks
pass. The complete experiment is reproducible from the recorded setup, the three
accepted Real booklets and failed predecessors remain inspectable, and no claimed
result exceeds its evidence. No production deployment, PDF/export work, broad
cleanup or additional agent platform is part of closeout.
